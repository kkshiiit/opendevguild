# Roadmap

Priorities follow verification gaps and user evidence. This is a plan, not a
claim that planned integrations, tests or releases have already happened. Consult
[verification](verification.md) for current execution and [requirements](requirements.md)
for the complete master-brief mapping.

| Priority | Deliverable | Completion evidence |
| --- | --- | --- |
| P0 | Reconcile the complete brief and exchange/gate contracts | Eighteen-element skill mapping, allowed lifecycle/gate/mode tests and no contradictory current instructions |
| P0 | Validate the eight core procedures before catalog acceptance | Official format checks, routing/functional/safety cases and reviewed core findings |
| P0 | Verify the complete local candidate | All 34 skill checks, relevant functional/security/regression tests, archive inspection and honest open-gate record |
| P0 | Test optional eight-role Codex integration or document the client limitation | Syntax/fields plus observed native loading/delegation where supported; serial fallback otherwise |
| P0 | Establish an authorized public project destination | Actual maintainer/owner, collision check, visibility, confidential reporting path and permission to publish |
| P1 | Expand live behavioral coverage beyond smoke samples | Matched controls, held-out prompts, fixed rubric, repeated runs and full retained outcomes |
| P1 | Exercise more realistic isolated fixtures | Repository changes, malicious-file instructions, scope preservation, unavailable tools and independent review |
| P1 | Confirm discovery/install/update/uninstall across supported clients | Fresh-client evidence, selected names only, collision refusal, preserved local edits and explicit OS matrix |
| P1 | Run hosted CI and dependency/secret scans for a real repository | Remote workflow URL, exact revision, scan scope and unresolved findings |
| P2 | Improve selection from observed errors | Measured false positives/negatives on representative ambiguous and multi-skill requests |
| P2 | Measure agent resource cost under controlled conditions | Exposed token/time/tool metrics, declared workload and uncertainty; no proxy promoted to actual usage |
| P2 | Evaluate public plugin distribution | Reviewed package, fresh-client behavior, completed platform review and actual published identity |

New skills require a distinct responsibility, concrete scenarios, maintenance
ownership and evidence that an existing skill cannot reasonably cover the task.
Avoid expanding the catalog to conceal incomplete testing of current procedures.

Español: primero cerrá contradicciones, controles esenciales y límites de
integración. Después ampliá escenarios reales y comparaciones reproducibles.
Publicación, soporte multiplataforma y ahorro de recursos necesitan evidencia
propia; no se deducen del tamaño del repositorio ni de pruebas de formato.
